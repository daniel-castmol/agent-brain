# Session — brain v1 kickoff

## Context

Continuing a discussion about Obsidian-vault-as-AI-memory architecture
that started with a question about whether agent memory frameworks like
basic-memory and memsearch were a real category. They are. Decided to
build a personal version (`brain`) targeted at Claude Code on a
WSL2/Linux dev machine.

## Decisions

- Fresh agent-only vault, kept separate from the existing `digital-brain`
  Obsidian vault. Cleaner conventions, no risk of polluting personal
  notes.
- English-only embeddings via `bge-small-en-v1.5` (384d). Faster and
  smaller than the multilingual alternative; can swap to `bge-m3` later
  if Spanish content becomes a meaningful share of the vault.
- DuckDB as silver+gold, with `vss` HNSW deferred until vault size
  justifies it. Brute-force `array_cosine_distance` is fine for now.
- Hybrid retrieval (vector + FTS via RRF) shipped in v1. Single-mode
  retrieval not enough.
- MCP stdio transport, four read-only tools to start: `search_notes`,
  `read_note`, `list_recent`, `find_related`. Write tools deferred to
  v2.

## Built

- `src/brain/` — config, parser, chunker, embedder, store, indexer,
  server, cli
- `tests/test_parser.py`, `tests/test_chunker.py` — pure-function
  coverage, 9/9 green
- `pyproject.toml` (uv), `.gitignore`, `README.md`
- `CLAUDE.md`, `tasks/todo.md`, `tasks/lessons.md` for handoff to
  Claude Code

End-to-end verified: `uv sync`, `brain init`, `brain index` (downloaded
the model, indexed the seed README), `brain status` (1 note, 2 chunks,
1 link). 9/9 tests pass.

## Next

1. Wire brain into Claude Code via `claude mcp add --scope user --transport stdio brain -- uv --directory <abs> run brain serve`.
2. Drop these seed notes into `~/brain-vault/` and re-index.
3. Sanity-test by asking Claude Code about something we discussed —
   should call `search_notes` and surface the design rationale note.
4. Then move on to v2 write-back: `write_note` + `append_to_note` MCP
   tools and a `SKILL.md` that teaches Claude Code when to call them.
